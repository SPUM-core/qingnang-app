> 审计对象：`E:\工作\qingnang-APP\frontend` + `design-assets`

## 0. 先说结论

这个项目的**设计资产质量高于绝大多数同类项目**——`design-assets/ui-kit` 里有完整的设计令牌、Logo 三组合、8尺寸 AppIcon、24枚线性图标、三尺寸启动页，甚至写清了「按钮高 56 圆角 28、卡片描边 45% 松烟绿」这种实现级细节。

**问题不在设计，在落地。**

| 核查项 | 结果 |
|---|---|
| `var(--qn-*)` 引用次数 | **0 次**（令牌文件从未被 import） |
| `.css` 文件数量 | **0 个**（样式全在 SFC 的 `<style scoped>` 里） |
| 实际色值种类 | **165 种** |
| 同一「青囊绿」的值 | **5 个**（#17534C / #1A4D45 / #2A6B62 / #2E7D6A / #45C4A8） |
| 响应式断点 | **13 种**（480/600/640/720/860/900/960…） |

`App.vue` 里其实**已经把 UI Kit 令牌重新实现了一遍**（`--qingnang-emerald: #17534C` 并注释「对齐 UI Kit Design Tokens v1.0」），但：① 换了变量名，与 `tokens.css` 语义重复；② 组件层又在此之外各自硬编码，**令牌只覆盖了 422 处中的前一层**。

结果就是：改一次品牌色要翻 28 个文件；UI Kit 里定的「45% 描边」在组件里根本没出现；暗色主题只覆盖了用变量的部分，硬编码白底的 6 处会漏。

## P0 · 收编 165 种颜色为约 20 个

### 问题

主色 5 个近似值并存，是"看起来不够精致"的**首要原因**。人眼对同一色的细微差异极其敏感，尤其在大面积相邻时——这正是"设计感"的来源。

高频对照：

| 实际值 | 出现 | 应对|
|---|---|---|
| `#1A4D45` | 34 次 | → `--qn-emerald`（这是自造色，UI Kit 无此值） |
| `#17534C` | 14 次 | → `--qn-emerald`（正牌，保留） |
| `#2A6B62` / `#2E7D6A` | 7 / 9 | → `--qn-emerald-light` |
| `#45C4A8` | 12 次 | → 用 `--qn-emerald-light`；**若作强调色需论证是否入规范** |
| `#A8442F` / `#C62828` / `#D84315` | 12 / 8 / 22 | 朱砂系统一到 `--qn-cinnabar`；警示文案另留 `--qn-danger` |
| `#E8F5E9` + `#2E7D32` | 多处配对 | 木色 chip 成对出现，合并为 `--qn-wood-bg` / `--qn-wood` |

### 建议

**分两批做，不要一次全换**（避免视觉回退难以定位）：

```bash
# 第一批：主色漂移（收益最大，影响约 100 处）
cd frontend/src
# #1A4D45 / #123F3A / #2A6B62 → 品牌主色系
grep -rl '#1A4D45\|#2A6B62' --include='*.vue' . \
  | xargs sed -i 's/#1A4D45/var(--qn-emerald)/g; s/#2A6B62/var(--qn-emerald-light)/g'

# ⚠️ 渐变里的色值需手工处理，sed 会破坏 linear-gradient 语法
# 例：linear-gradient(135deg, #1A4D45, #2A6B62)
#→ linear-gradient(135deg, var(--qn-emerald), var(--qn-emerald-light))
```

**第二批：语义色归并**（警示/成功/失败），并**顺手补暗色适配**。

⚠️ **重点修6 处硬编码白底**——它们在暗色模式下是刺眼白块：

```bash
grep -rn 'background: #fff\|background: #FFF\|background: white' --include='*.vue' .
```

改为 `background: var(--qn-surface)`。这一步是暗色主题从"基本可用"到"完全可用"的关键。

## P1 · 13 种断点收敛为 4 档

## P1 · 可访问性补齐（老年产品的刚性需求）

### 事实

- `<img>` 8 个，**`alt` 只有 5 个**
- `aria-label` 只在 8 个文件出现，图标按钮（`QIcon` 组件）**统一 `aria-hidden="true"`**——纯图标按钮对读屏用户等于不存在
- 触控目标：多处按钮 `padding: 6px 12px` + 14px 字，实际高度约 30px，**低于 44px 建议值**

### 建议

**1. 纯图标按钮必须补标签**（`LayoutShell.vue` 的铃铛、个人中心入口即是）：

```vue
<!-- ❌ 读屏只念"按钮" -->
<RouterLink to="/notifications" class="action-bell">
  <QIcon name="bell" :size="19" />
</RouterLink>

<!-- ✅ -->
<RouterLink to="/notifications" class="action-bell"
            aria-label="提醒通知" title="提醒通知">
  <QIcon name="bell" :size="19" />
</RouterLink>
```

`QIcon.vue` 保持 `aria-hidden="true"` 是**对的**（图标本身不该被朗读），但**父按钮必须承担标签**。这条不改组件，只改调用处。

**2. 装饰性图片 `alt=""`，信息性图片写描述**：

```vue
<!-- Logo：紧邻品牌文字，装饰性 -->
<img src="/assets/logo/icon-light.png" alt="" class="brand-icon" />
<!-- 体质雷达图：信息性 -->
<img :src="chartUrl" alt="五形体质分布雷达图：木30火45土20金35水70" />
```

**3. 表单 label 关联**（`QuestionnaireView` / `SettingsView` 有 25 个 `<label>` 但需确认都有 `for`）：

```vue
<label for="birth-date">出生日期</label>
<input id="birth-date" v-model="form.birthDate" />
```

**4. 触控目标统一提到 44px**——已在 `base.css` 的 `.btn` 里设 `min-height: 44px`，组件内若有小尺寸按钮，用 `.btn--sm` 变体但保持 `min-height: 36px` + 增大外层padding 命中区（不要直接缩到 30px）。

## P2 · 图表配色与暗色主题对齐

`DriftChart.vue` / `RadarChart.vue` 用 echarts，但配色是硬编码的。**echarts 不会自动跟随 CSS 变量**——暗色模式下图表会保持浅色系，与深色背景割裂。

```js
// src/utils/chartTheme.js —— 单一来源，主题切换时重建实例
const css = (n) => getComputedStyle(document.documentElement).getPropertyValue(n).trim()

export function chartPalette() {
  return {
    text:    css('--qn-ink-2'),
    line:    css('--qn-line'),
    primary: css('--qn-emerald'),
    wuxing:  [css('--qn-wood'), css('--qn-fire'), css('--qn-earth'),
              css('--qn-metal'), css('--qn-water')],
    bg:      css('--qn-surface'),
  }
}

// 主题切换时需重设option —— 因为 CSS 变量值变了，但已渲染的 canvas 不会更新
export function onThemeChange(cb) {
  new MutationObserver(cb).observe(document.documentElement,
    { attributes: true, attributeFilter: ['data-theme', 'data-font'] })
}
```

⚠️ 注意：`--fs-scale` 变化（用户调字号）也会影响图表，需一并重建。

## P2 · 三处体验细节

**1. 加载态缺失**——`DashboardView` 调`/reasoning/lifestyle` 期间无骨架屏。建议加轻量骨架（`shimmer` 用 `--qn-bg-paper` 渐变，不引新依赖）。

**2. 商城用 emoji 当封面**（`ShopDetailView.vue:266` `.cover-emoji { font-size: 120px }`）——与"新中式极简科技风"严重冲突。建议改为统一线性图标或占位纹样。

**3. Logo 是位图**（ui-kit README 自己标注了：单边 ≤500px，放大易虚）——定稿后矢量重绘。`design-assets/logo/vector/` 已有 3 个 SVG 方案，可直接替换。

| 3 | 主色归并（`#1A4D45` / `#2A6B62` 等） | **中** | 分文件改，每改完目视对比 |
| 4 | 6 处硬编码白底 → `var(--qn-surface)` | 低 | 暗色主题完整性的关键 |
| 5 | 断点归并到 4 档 | 中 | 需逐页检查布局 |
| 6 | 原子类 `.btn` / `.card` / `.tag` 逐页迁移 | 中 | **逐页做，不要批量 sed** |
| 7 | a11y：图标按钮 `aria-label` / img `alt` / 44px 触控区 | 低 | 可与 6 同步 |
| 8 | 图表主题跟随 | 低 | 独立文件，无侵入 |

⚠️ **第 3、5、6 步都会改变视觉，必须逐页目视验证。** 前两步（建文件 + 改名）是纯地基，做完后再动视觉，出问题能立刻定位是哪一步引入的。

---

## 不建议做的事

- ❌ **不要重做视觉设计** —— UI Kit 的色板、圆角、间距、图标规格都是对的，问题在落地不一致，不在设计本身
- ❌ **不要引入 UI 框架**（Vant / Element Plus / Naive UI）—— 新中式风格 + 五形语义色是差异化优势，套框架会把品牌特色冲掉，且与现有 28 个组件全量重写
- ❌ **不要上 Tailwind** —— 同上，且 4300 行已写样式，迁移成本高。CSS 变量 + 原子类已足够
- ❌ **不要为了"简洁"删掉老年关怀与暗色主题** —— 这是中医适老产品的核心价值，不是冗余
- ❌ **不要动 `QIcon` 的 `aria-hidden`** —— 组件设计是对的，要改的是调用处的 `aria-label`
- ❌ **不要一次性 sed 全量替换样式** —— 局部覆盖会被误伤，且视觉回退难定位

---

## 一句话总结

**设计不缺，缺的是把设计落地成代码的那一层。**

第一步只需建两个 CSS 文件并引入，零风险；第二步把 16 个变量改名对齐，仍是零风险。做完这两步，"改一次品牌色要翻 28 个文件"就变成了"改一行"。之后所有美化动作——主色归并、原子类、暗色补全——才有了可靠的地基可站。
