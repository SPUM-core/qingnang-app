## 一、把作者判定翻译成机器可执行的三条

| # | 判定 | 含义 |
|---|---|---|
| 1 | **健康 = S ∈ H** | H 是绝对区间，**不随人移动**。这是唯一健康判据 |
| 2 | **S₀ = 起点事件** | 出生瞬间接入地球子网时已被拉偏，**这个拉偏大概率会被持续**（非可逆归零） |
| 3 | **S₀ 的职责是预测，不是靶心** | 推理人生轨迹线、预测某周期大概率出现哪类病症、梳理因果链的起点 |

**关键推论（判定 1+2 的合成）**：
- 「回归 S₀」是**因果断裂**——S₀ 本身是偏离态，回归它等于把拉偏当靶心
- **S₀ 偏离 H ≠ 病**。它是体质坐标系，不是不健康指标
- ΔV = S_current − S₀ 的意义是**轨迹位移**（预测用），**不是健康距离**
- 健康距离 = S_current 距 **H** 的距离，与 S₀ 无关

## 二、代码现状：与判定 1 方向相反（最重的一处）

### `trajectory_algorithm.py:490-488` normalize_S_effective

```python
# 核心思想: 每个人的"零健康"基线不同，先天 S_0 偏离中心的部分
# 不应被计为"异常"。此步骤消除个体先天差异，使健康判定
# 基于"偏离自身基线"而非"偏离绝对中心"。
s_eff[dim] = S_current[dim] - (S_0[dim] - H_centroid[dim])
```

**代数展开**（实测推导）：
```
判定 S_eff ∈ [lo, hi]
⟺ lo ≤ S_cur − (S₀ − H) ≤ hi
⟺ lo + S₀ − H ≤ S_cur ≤ hi + S₀ − H
```
即**健康区间整体平移 +(S₀ − H)**，区间中心从 `H` 移到 `S₀`。

实测：
| S₀[土] | 等价健康区间 | 区间中心 |
|---|---|---|
| 50 | S_cur[土] ∈ [40, 60] | 50（= H，正常） |
| 43 | S_cur[土] ∈ [33, 53] | **43 = S₀** |
| 20 | S_cur[土] ∈ [10, 30] | **20 = S₀** |

**结论**：这个函数**在数学上把 H 重新定义成了以 S₀ 为中心**，与判定 1「H 绝对不随人移动」**直接矛盾**。
代码注释自陈的「健康判定基于偏离自身基线而非偏离绝对中心」，正是作者刚刚否掉的那一种读法。

**这不只是量纲问题**——它是**靶心错误**。量纲错配（P0-1）会得出反向结论，靶心错误会让**方向本身就错**：
用户在 S₀ 方向上加深偏离，反而被判得更"健康"。

### 同一模块内三处 HEALTH_CENTROID 语义互不一致

| 行 | 用法 | 隐含的语义 |
|---|---|---|
| `510` | `innate_bias = S_0 − H_centroid`（消除先天） | **H 随人而动** ← 与判定 1 冲突 |
| `676` | `target = HEALTH_CENTROID[dim]`（删除力向中心拉） | **H 是绝对靶心** ✅ 与判定 1 一致 |
| `465` | `centroid = HEALTH_CENTROID[dim]`（算 σ 偏离度） | 仅作**度量原点**，无判定含义 ✅ |

**同一常量在同一文件里承担了两种互斥语义。** `676` 的帧动力学已经按
「H 是绝对靶心」在拉回了，`510` 却把 H 平移走——两套判定并存，
`health_polytope_margin` 用的正是被平移后的 `S_eff`（`562`）。
