# qingnang-APP 代码审计 · 面向「SPUM 输出平台」定位

> 日期：2026-10-07
> 定位：**为加载了 SPUM 中医思想的 AI 提供输出平台**
> 审计维度：① SPUM 投影保真度 ② 会产生错误输出的真实代码缺陷
> 方法：只做事实比对与断点登记，不主张理论应如何修改（判定权归作者）

---

## 0. 一句话结论

**平台侧（代码）有 4 个 P0 缺陷会导致 AI 拿到错误输入或整个 `/chat` 500**；
**投影侧（system prompt 与 spum-core 权威源）有 2 处实质不一致、5 处关键源文档断言未注入**。

其中最严重的一条不是代码 bug，而是**量纲错配**：
`trajectory_algorithm.py:57-61` 的注释**自己写明了**两个量纲体系不可混用，
而 `assistant.py:369-370` 恰好把 center=20 的 `v_innate` 套进了 center=50 的 45/65 阈值，
结果是**「五形全部偏弱」**——且这句话被写进 system prompt，直接驱动 LLM 推理。

## 一、P0 代码缺陷（已实测复现，非推断）

### P0-1量纲错配 → 「五形俱废」反向结论 ★ 本次最严重

**位置**：`assistant.py:369-370`（→ `380-381` 注入 prompt）、`assistant.py:402-404`、`assistant.py:3638-3639`、`knowledge.py:57-58`、`cases.py:82-83`

**事实**：`trajectory_algorithm.py:57-61` 明文警告：
> `v_innate`: 藏干概率分布，Σ=100，每维期望=20
> `HEALTH_CENTROID`: 多面体健康标量空间，各维独立 50±range
> **两者不要统一** — 曾菊心/曾银鸾大运曲线依赖此 50 值

`cases.py:711-712/724-725` 建档时把 `v_innate`(center=20) 同时写入 `v_baseline` 与 `v_current`。
`assistant.py:365` 读 `case.v_current or case.v_baseline` →拿到的就是 center=20 数据。
`assistant.py:3673` 的 `_V_INNATE_MEAN = 20.0` 证明**代码库自己知道**这个口径，
但 369/370仍按 45/65 判定。

**实测**（seed 高素娟真实 `v_innate = {wood:20, fire:18, earth:43, metal:20, water:0}`）：
```
偏弱: 木、火、土、金、水← 五形全部
偏强: 五形调和
```
`earth:43` 实际是该用户最强的土壅（seed 注释写明"土壅埋木"），却被判为偏弱，**结论方向完全相反**。
且`_generate_generic_reply` 会据此回答"你的木形偏弱，睡眠是补它最直接的方式"——建议与体质相反。

**影响面**：任何**刚建档、还没做PPG 的用户**（即新用户首日体验）。
唯一写对的是 `cases.py:85-86`（用了 `label.get(w, w)` 兜底，但阈值仍是 45，口径仍错）。

**登记**：阈值不能简单取一个数。仓库里至少 3 种口径并存（center=50 标量 / center=20 概率分布 / `HEALTH_POLYTOPE` 各维不等宽 35-65、30-70、40-60、38-62）。**根因是消费端不知道自己在处理哪种量纲**。

### P0-2 sigma/tau 键污染 → KeyError → `/chat` 500

**位置**：`assistant.py:369-370` → `380-381`；同源 `assistant.py:402-404`、`3638-3642`、`knowledge.py:57`

**事实**：`trajectory_algorithm.py:486-487` 的 `normalize_S_effective` 在 5 个五形维度之外
**额外塞入 `sigma`、`tau` 两个键**（`ppg.py:534` 写入 `v_current`）。
`weak = [w for w, val in vc.items() ...]` 遍历全字典，二者都是 float 且 < 45，**必然**入选。
随后 `wuxing_labels['sigma']` 抛 KeyError。

**实测**：
```
v_current keys = ['wood','fire','earth','metal','water','sigma','tau']
weak = ['fire','water','sigma','tau']
*** KeyError -> 'sigma'
```

**为何致命**：`build_system_prompt` 在 `assistant.py:1139` 被调用，**位于任何 try 块之外**
→ 整个 `/chat` 返回 500。**只要有PPG 观测记录的用户就无法与 AI 对话**，前端只见通用 500。

### P0-3 `delta_f` 为 NULL → AttributeError → `/chat` 500

**位置**：`assistant.py:284-287`

**事实**：`delta_f` 是 nullable JSON 列（`models/observation.py:19`，无 default）。
`ppg.py` 的三条失败路径（`_fail()` 410 / bridge 失败 444 / pipeline 异常 485）都是
**先 `db.add(ob); db.commit()` 建行**，之后才改 `status="failed"` → 这些行 `delta_f` 永远是 NULL。
任何一次波形采集失败即触发 `AttributeError: 'NoneType' object has no attribute 'get'`。
同样在无保护区，同样 500。

**附带**：若 `delta_f` 非空但值为 str（未跑 `_sanitize_vector_dict` 的写入路径），
`:+.2f` 抛 `ValueError`。对比 `ppg.py:581` 做了清洗，此处没有。

### P0-4 异常变量未绑定 → 静默降级 + 诊断信息彻底丢失

**位置**：`ai_response.py:351`

```python
except Exception:                #← 没有 as e
    print(f"[normalize_parsed] Pydantic validation failed: {e}")   # ← 引用未定义的 e
```

**后果链**：本该"记日志返回 None 走 fallback"的降级路径，变成 `NameError`抛出。
调用方 `assistant.py:1337/1370` 在 try 内 → `1345` 的 `except` 把它吞成"LLM 不可用"
→ **本应展示的 LLM 回复被替换成规则模板**。故障不可见 + 连日志都打不出来。

**已核实这是全backend 唯一一处**该模式，其余 20+ 处都正确写了 `as e`。

## 二、投影保真度：system prompt vs spum-core 权威源

核查范围：`assistant.py:149-220`（`spum_worldview`，注入 LLM 的世界观片段）
权威源：`spum-core/五行/医学/` 实际 5 篇

### 一致的部分（无需处理）

逐条比对吻合：五形拓扑定义（水传输/木骨架/土储备/金修剪/火梯度）、
五脏图论定义（肾最低σ区/肝环锁定区/肺修剪高频区/心最高代谢区/脾储备池）、
折叠晶体解Ⅳ/解Ⅴ、耦合动力学链条顺序、精力公式 `S_土 × S_火 × dv/dt`、
无病实体论水波隐喻、饮食=边界整合三分、节气振荡方向（含立春↑↑非↑↑↑）、
子午流注三时辰（含"午时升提药极端慎用"）。

### 不一致 2 处（影响最大）

**(1) 健康定义：prompt 把健康重定义为"接近先天基底"，源公理是 `S ∈ H`**

- `assistant.py:214`「健康 = 五形向量接近先天基底。偏离 = 网络正在经历结构性张力。」
- 源 `spum-古中医无病实体论.md:729`「**健康公理**：存在一个平衡区间 $H \subset \mathbb{R}^5$，$S \in H$ 即为健康」
- 源 `:682`「健康不是某一个分量的绝对数值——健康是五个分量之间的**平衡关系**」
- 源 `:731`「治疗公理：一切治疗行为都是 ΔS 操作——将 S 推回 H 边界内」

连带 `assistant.py:215`「调理 = 引导拓扑结构回归先天相位」把目标从 `S ∈ H` 换成了回归 `S_0`。
另注：源 `:702-704` 明确定性 S_0「不是宿命，而是体质坐标系」。

**(2) 时间帧公式漏月相、增无源项、混并两条公式**

- `assistant.py:197`：`S(t) = S_base + ΔS_节气 + ΔS_日干支 + ΔS_时辰 + ΔS_观测漂移`
- 源 `spum-药性天时耦合.md:131`：`S(t) = S_0(birth) + ΔS_season + ΔS_lunar(phase) + ΔS_hour(meridian)`

三处差异：① 源含 `ΔS_lunar(phase)` 月相调制（源另有专节 §4.4 及月相表），**prompt 完全遗漏**；
② prompt 的 `ΔS_观测漂移` 在医学 5 篇中检索零命中；③ `ΔS_日干支` 在源中属另一条独立公式
（`:168` `S(t_day) = S_0 + ΔS_节气 + ΔS_天干 + ΔS_地支`，源为天干/地支二分），prompt 混并为一项。

**另需注意**：源 `spum-药性天时耦合.md:3` 置于文件开头的**强制历法规则**（所有时间参考以农历为准，
公历必须转换）未被注入。prompt 注入了全套节气/时辰/子午流注推算能力，但没注入这条会直接导致推算错误的执行性约束。

### 源有prompt 无（P0 级，直接决定输出正确性）

| 缺失项 | 源位置 | 为何关键 |
|---|---|---|
| **健康公理的 H 平衡区间本体** | `无病实体论:729` | 源用 H 界定健康，prompt 未注入 H，且被上述错误定义取代 |
| **治疗终点判据** | `无病实体论:636` 「治疗的终点不是指标正常，而是**停药后身体能维持平衡**」 | 判定调理是否完成的唯一标准；prompt 只写"调好就停" |
| **五行偏性判据 μ_min/μ_max** | `无病实体论:686-694`、`spum-病机五形失衡检测.md:63-64` | `S_木 ≤ μ_min → 木散`、`≥ μ_max → 木僵`。**prompt 只给健康态，无任何偏离态命名与阈值** —— 而输出平台的核心任务就是"观测漂移"，无判据则无法定性漂移 |
| **西药依赖三阶桥接** | `spum-中西医范式桥接研究.md` 全篇 | A/B/C 型鉴别、并行→桥接→维持期、减量 ≤10-20%。源自述"纯中药场景越来越少"，这是现实场景的核心能力 |
| **毒性涌现推导链** | `无病实体论:743-884` §9 全章 | prompt 只用 GT-005 解释毒素，缺"毒性=集群尺度涌现策略"结论 |
| **四推论** | `无病实体论:732-735` | 抗病治疗不存在/ 固定方药必然无效 / 手术切除不调 S 复发是拓扑必然 |

### 需作者注意的一处诚实性问题

`assistant.py:155`「**完备性定理：恰好五个，不多不少**」——
该定理实际出自 `五行/spum-五形完备性.md`（**不在医学 5 篇内**），
且该文件自附验证范围声明：脚本只验证了覆盖性（充分性），
**语义独立性（必要性）的实证检验"规划见 §9.2-9.3（待执行）"**。

即prompt 以既成事实语气注入了一个源方自标实证未完成的合取结论。
**此处只登记事实，不主张改动** —— 但输出平台若对外宣称"恰好五个"，需知道源方自己的标注。

### P1 级缺失（影响输出质量，非崩溃）

- `ΔS_effective = ΔS_base × f_节气 × f_时辰 × f_月相`（`药性天时耦合:312`）—— prompt 只有"×2"无数值结构，无法插值
- 药物相位→脏腑映射表（`:112-118`）—— 食疗/药膳的直接依据，prompt 只注脏腑解剖对应
- 12 经络完整时辰表（`:216-227`）—— prompt 只3 个，缺丑时（疏肝 ×2.0）、寅时（肺经 ×2.0）
- **精力方向性边界**（`气运新论:66`）「精力只放大变化幅度，**不指向具体方向**。方向来自抉择的质量」—
  **缺失风险最高的一条**：这是防止 LLM 对用户作"多运动→运气变好"类承诺的关键约束
- 统计确定性/概率是认知投影（`气运新论:70-92`）—— 避免 SPUM 被说成"玄学概率论"的核心防线

| P1 | `assistant.py:4165` | `f"{top_s}{top_s}通明"` 字符串重复 → 输出"木木通明"（无 LLM 降级路径必经） |

## 四、修复顺序（有依赖，不可跳步）

1. **P0-4**（`ai_response.py:351` 补 `as e`）—— 一行，零风险，先恢复故障可见性
2. **P0-2 + P0-3**（`assistant.py:284-287` 加 None 守卫；`369-370` 改用显式五形白名单而非遍历全字典）—— 消除 500
3. **P0-1**（量纲）—— **必须先定标尺再改**，不能只换数字。
   最低成本方案：在工具函数层给每个向量显式标注量纲（如 `Vector(v, space="prob"|"scalar")`），
   让消费端无法误用。这一步是根因，不做则 P0-1 会在别处复发
4. 投影侧断点（健康定义/时间帧公式）—— **属理论判定，等作者定夺**，我只登记
5. 其余 P1/P2

**明确劝阻**：不重写微服务、不上完整可观测栈、不动理论链路、
不因"完备性定理实证未完成"就主张删改prompt（源方自己的诚实标注，不是缺陷）。
